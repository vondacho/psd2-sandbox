> **Status:** proposal generated by AI on 2026-09-22 from two inputs — the Berlin Group
> *NextGenPSD2 XS2A Framework Implementation Guidelines* v1.3.16 (`SRC-IG`) and the bank's
> architecture decision record (`SRC-ADR`, `docs/context/adr.md` @ `7c44c2d`) — following the

## What this is

A connected set of software-intent artefacts: the problem and the journey, the domain as a
timeline and as a set of boundaries, the plan for slicing it, the behaviour that needs
illustrating, the architecture and its contracts, two delivery packs, and a register of
everything nobody has decided.

## Pack root

This directory mirrors the layout `docs/ai/10-artifact-contract.md` prescribes. Every path inside
these artefacts — including the manifest and the generated feature headers — is relative to
**this directory**, so the whole pack can be promoted to the repository root unchanged once it is
accepted. The validator is run with `docs/result/` mounted as its root; see
[`traceability/validation-report.md`](traceability/validation-report.md) §1.

## The four things a reviewer should not skim past

- **A PSU cannot withdraw a TPP's access at the bank.** The only consent screen belongs to the TPP (`C-07`, `D-09`).
- **The bank answers for a consent record Finologee holds.** (`C-08`, `D-01`, `RSK-07`).
- **Nothing shows a payment's amount and payee before the PSU confirms.** (`C-09`, `Q-17`, `RSK-08`).
- **31 red cards across eight example maps.** That is the measure of how much of this is still a proposal.

## Regenerating the projections

```
python3 docs/ai/tools/em_to_feature.py        # .examplemap -> .feature
python3 docs/ai/tools/validate.py             # the whole pack
```

Both tools hard-code the `docs/` and `tests/` prefixes and are run with this directory mounted as
their root until the pack is promoted.
